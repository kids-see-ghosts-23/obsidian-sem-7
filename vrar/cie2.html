Unit 2 · Prefabs

CIE-3 Q1b (4M)

Why Unity is popular

Unity is an industry-leading engine for 2D, 3D, AR and VR. It gives one integrated environment where you design scenes, manage assets, write scripts and test in real time.

  • Cross-platform: build once, deploy to Android, iOS, AR devices and VR headsets.
  • Component-based: a GameObject gets abilities by attaching components (Transform, Renderer, Collider, Scripts).
  • Built-in Scene Editor, Asset Management, Physics Engine, Animation and Lighting systems.
  • Prefabs make objects reusable and consistent, improving productivity and organisation.

What is a Prefab?

Think of it as a stamp. A Prefab is a reusable template of a GameObject that stores its components, scripts, properties and child objects in one asset. You use it many times across scenes with the same look and behaviour, and when you change it in one place every instance updates. That keeps things uniform and reduces errors.

CIE-2 Q1.1 (2M)

Prefab Asset vs Prefab Instance

The asset is the master copy in the Project folder; it defines structure, components and default properties. An instance is a copy of it placed in a Scene. Instances stay linked to the asset, so changing the asset updates all of them, but an instance can also have its own overrides without touching the original.

A plain GameObject exists only in its current scene; a Prefab is a template you can copy into many scenes.

CIE-2 Q1a (6M)

Creating and placing Prefabs

Create GameObject → Add components/scripts → Drag Hierarchy to Project → Prefab Asset → Drag into Scene

Build the object in the Scene and add what it needs. Dragging it from the Hierarchy into the Project folder makes the Prefab Asset (blue cube icon). Dragging the Prefab back into the Scene makes an instance, as many as you like. To edit, work in the Scene or in Prefab Mode (blue background), then Apply or Revert.

Reuse and organisation: one asset is the single source of truth, so reuse across scenes saves time, keeps objects consistent and keeps large scenes tidy and easy to maintain.

Apply, Revert and Overrides

You can change one instance locally and it stays linked. Apply saves those changes back to the asset and so updates every instance (add a component to one, click Apply, all get it). Revert throws the local changes away and restores asset values (a test colour is undone).

Overrides are properties of an instance that differ from its asset, such as transform, components, material or script values. They affect only that instance. Unity shows modified fields in bold or highlighted and lists them in an Overrides dropdown, where you can revert one or use Revert All. Result: local customisation without breaking the link.

Nested Prefabs vs Variants

Nested: prefabs placed inside other prefabs as children, for complex structures such as a character with equipment or a UI panel; changes to a child propagate up the hierarchy. Variant: a specialised version of an existing prefab that inherits everything and overrides selectively (enemy types, UI styles), so you customise without changing the original.

Runtime instantiation

Creating objects while the game runs rather than placing them beforehand, using Instantiate() to make prefab copies. The prefab is usually assigned through a public variable, and you can choose position and rotation. It is triggered by player actions (shooting, collecting), timers or waves (enemy spawners) and game events. Used for enemies, projectiles, power-ups and procedural levels, and works well with object pooling to cut overhead.

UI Prefabs, pros and cons

Buttons, panels, menus, dialog boxes and HUD elements are designed once and reused, so a change to colour, font or function updates every copy. They work with Unity's Canvas and Event System.

Advantages: reusability, consistent design, easy maintenance and debugging, faster prototyping, team collaboration. Disadvantages: too many overrides make it hard to tell base from overridden values, nested prefabs complicate debugging, poor organisation and unused prefabs create clutter, and it needs disciplined management.

Example, Enemy prefab: visuals, scripts and physics (health, movement, attack, animation) built once. Changing health or speed in the prefab updates every enemy, and parameters can be tweaked for harder variants.

Chapter 9 · Working with Objects

Programming is mostly organising data. Even bool, int, float and string are objects, and objects can contain other objects (a Person has firstName, lastName, birthdate).

A class is a template for structure and behaviour; an instance is a copy with its own data (the Person class gives john, sarah, mike). Classes use PascalCase, variables camelCase.

  • Instance variables live in the class block for the object's whole life. Local variables live inside a method and are destroyed when it returns.
  • Uninitialised defaults: int and float 0, string null, bool false.
  • Item item = new Item(); creates an instance; item holds a reference. Members are reached with the dot operator.
  • public members are visible outside and in the Inspector; private (the default) are hidden. This is encapsulation: expose only what is needed.
  • Methods hold an object's behaviour, are called through an instance (item.LogInfo()), and use member names directly. DRY (Don't Repeat Yourself): write it once in a method so a fix happens in one place.

A constructor is a special method that initialises a new instance. this means the current instance and fixes name clashes: this.name = name; (field on the left, parameter on the right).

public Item(string name, int worth, bool canBeSold) {
  this.name = name; this.worth = worth; this.canBeSold = canBeSold;
}
Item item = new Item("Goblin Tooth", 4, true);  // one line instead of four
Declaring a custom constructor removes the automatic default one, so new Item() becomes a compiler error.

Static members belong to the class and are shared (for example a counter incremented in the constructor), accessed as Item.NumberOfInstances. A static method has no this, so it can access only static members. Instance members: one copy per object, accessed with item.

Chapter 10 · Working with Scripts

A script is a class that inherits MonoBehaviour, which gives it Unity powers. Unlike a regular class (made with new), it is created by attaching it to a GameObject, or at runtime with Instantiate(). The using lines pull in namespaces, containers that organise code like folders, so you can write Debug.Log() instead of the full path.

CIE-3 Q4 (2M)

Default methods: Start() runs once on startup for set-up; Update() runs every frame for continuous behaviour such as rotation or movement. Variables go at the top of the class.

  • File name must match the class name exactly (case sensitive, no spaces, .cs). Otherwise the script cannot be attached.
  • Attach by dragging the script onto the GameObject, or Inspector, Add Component.
  • Public variables appear in the Inspector and can differ per GameObject, even edited live; they revert when play stops. Private ones stay hidden.
  • Vector3 holds X, Y, Z for a position or direction. transform and gameObject always exist in a script.
  • [HideInInspector] hides a public variable (it stays public). [Header("Text")] adds a bold heading to group variables. Attributes can be stacked.
public class SimpleRotation : MonoBehaviour {
  public Vector3 rotationPerSecond;
  void Update() {
    transform.Rotate(rotationPerSecond * Time.deltaTime);
  }
}

Time.deltaTime is the time per frame (1/60 s at 60 FPS). Without it speed depends on frame rate; with it motion is the same on any machine. Setting Y = 45 rotates 45 degrees per second around Y; negative values reverse it.

Advanced 3D Movement

CIE-3 Q3a (10M)

The aim is a first-person system with momentum, gravity and jumping. Momentum builds in the direction of held WASD keys, fades gradually after release, and builds faster when you reverse. You keep ground velocity in mid air, with reduced air control.

Local vs world space: WASD is relative to where the player faces (local), but CharacterController.Move needs world space. If velocity were stored locally, jumping forward then spinning 180 degrees would send you backward in the air. So detect input locally, convert at once with TransformDirection, and keep one world-space worldVelocity.

  • Normalise the input so W+D is not faster than W alone.
  • Dot product compares intended and current direction (1 same, -1 opposite); when negative, multiply acceleration so the player reverses quickly instead of sliding.
  • ClampMagnitude limits total speed (limiting X and Z separately gives square limits). If an external force (explosion) leaves you overspeed, clamp to the current magnitude so you are not slowed instantly.
  • Friction acts opposite to velocity only when grounded and (no input or over max speed). Snap-to-zero: if friction exceeds the remaining velocity, set it to 0, else it flips negative and jitters.
  • Gravity pulls yVelocity down when not grounded, capped at maxGravity (terminal velocity).
  • Collision flags: Below = grounded, Sides = wall bounce, Above = head bump (zero vertical velocity). A small -1 downward force keeps the controller grounded, and Move() is called only if magnitude is over 0.03 to save work and stop jitter.
Input → Friction → Gravity → Jump → Apply Movement
Jump sets yVelocity = jumpPower (= not +=) and grounded = false at once, or the next update resets velocity and cancels the jump.
public class ArrowMove : MonoBehaviour {
  public float speed = 5f;
  void Update() {
    float x = Input.GetAxis("Horizontal"), z = Input.GetAxis("Vertical");
    Vector3 dir = Vector3.ClampMagnitude(new Vector3(x,0,z), 1f);
    transform.Translate(dir * speed * Time.deltaTime, Space.World);
  }
}

Illustrative code, not in the slides: GetAxis eases between keys and deltaTime keeps speed frame-rate independent.

Primitives and triangles

The virtual world is a 3D Euclidean space where each point has (x, y, z). Surfaces contain infinitely many points but computers need finite data, so models are built from primitives, finite shapes standing for those points (stored efficiently in a Doubly Connected Edge List).

The triangle, a planar patch of three vertices, is the simplest 3D primitive. It is easy for algorithms and lets GPUs process huge numbers in parallel, and collision detection is much faster than with splines. Quadrilaterals may shrink file size but greatly raise computation. Moving even a huge mesh only means transforming vertices, since edges and faces connect them and keep the shape.

Translation and relativity of motion

Translation changes position only, not orientation or size (a rigid body transformation). Mathematically, moving an object equals moving the world's coordinate system the opposite way: a viewer moving forward is the world moving backward. The brain struggles to tell "I am moving" from "the world is moving".

CIE-2 Q2b (4M)

VR sickness: when visuals suggest the user is moving but the vestibular system (inner ear) feels no motion, or object motion is misread as self-motion. Example: a user sits still in a chair while the headset shows them moving forward; the eyes say moving, the inner ear says still.

CIE-2 Q1.5 vectionCIE-2 Q2a types of vection

Rotation: 2D, 3D, Yaw, Pitch, Roll

Rotation changes orientation. Start in 2D: a 2x2 matrix transforms (x, y), and its columns show where the axes go. Types: identity (no change), scale, mirror (flips), shear (slants), singular (determinant 0, shape collapses).

A valid rotation must not distort: columns of unit length (no stretching), perpendicular columns with dot product 0 (no shearing), determinant +1 (no mirror image).

2D formula (about the origin): x' = x cosθ − y sinθ, y' = x sinθ + y cosθ. For another pivot, translate, rotate, translate back.

CIE-2 Q3b (4M)CIE-3 Q5 (2M)

Degrees of Freedom

The number of independent motions: 3 for position (x, y, z) plus 3 for rotation (pitch, yaw, roll) = 6. A 3D rotation matrix starts with 9 components; unit length, perpendicular and no-mirror rules cut it to exactly 3 DOF. The more DOF tracked in VR, the more of the user's real movement is copied into the virtual world.

public class MouseRotate : MonoBehaviour {
  public float rotationSpeed = 200f;
  void Update() {
    float h = Input.GetAxis("Mouse X"), v = Input.GetAxis("Mouse Y");
    transform.Rotate(Vector3.up, -h * rotationSpeed * Time.deltaTime);
    transform.Rotate(Vector3.right, v * rotationSpeed * Time.deltaTime);
  }
}

Viewing Transformation and Chaining

CIE-2 Q3a (6M)

To render, we place a virtual camera (eye) in the world. The eye looks down -Z, X points right, Y up. The camera is defined by Look-At: eye position e, centre c (what it looks at) and up vector u. Vectors: ẑ = −(p−e)/‖p−e‖, x̂ = u × ẑ, ŷ = ẑ × x̂, giving three orthogonal axes.

CIE-2 Q5 (10M)CIE-3 Q5a (10M)

The chain: T = Tvp · Tcan · Teye · Trb

Goal: turn a model vertex (x, y, z) into a screen pixel. Matrices are applied right to left.

  • Trb moves the object to its place in the world.
  • Teye moves the world into the camera's frame.
  • Tcan = Tst·Tp: Tp makes the 4th component z, and hardware divides by it so distant objects shrink. Tst scales the viewing frustum (Near n to Far f) into a canonical cube from -1 to +1; anything outside is clipped.
  • Tvp scales [-1, 1] to the screen (e.g. 1920 x 1080) and shifts the origin to the bottom-left.

Algorithm: multiply the vertex by Trb, Teye, Tcan, Tvp in turn, or multiply the four once to get T and apply it to every vertex.

Stereo: one centre eye is assumed first. Real eyes are about 64 mm apart (IPD, t). For the left eye shift the world right by t/2, for the right eye left by t/2: Tleft = Tvp Tcan Ttrans(t/2) Teye Trb. The small offset creates parallax, which the brain reads as depth.

Motion and Physics

CIE-2 Q1.3 (2M)

VR often copies real physics (gravity, collision forces, motion) to feel natural, keep immersion and support interaction; sometimes it is adjusted to reduce motion sickness.

  • Velocity = rate of change of position (v = dy/dt); acceleration = rate of change of velocity (a = dv/dt). Gravity is 9.8 m/s² down: v = v0 − gt, y = y0 − ½gt².
  • In 3D, speed = √(vx²+vy²+vz²). A rigid body does not deform; its motion is translation plus rotation.
  • Circular motion: ω = dθ/dt, centripetal acceleration a = rω² toward the centre.
  • Simulation steps the state forward by a time step Δt: Euler x[k+1] = x[k] + ẋ·Δt is simple; Runge-Kutta is more accurate.
  • User input is added as control; it must feel responsive, predictable and natural.

Collision detection and response

Detection finds if and when objects touch (without it, objects ghost through each other); response decides what happens: bounce, slide, stop, vibrate, damage. Detection is two-phase:

  • Broad phase: quickly removes far-apart pairs using bounding volumes (sphere, AABB, OBB, convex hull; tighter means slower) or spatial partitioning.
  • Narrow phase: precise tests on the remaining pairs (triangle-triangle, edge and plane, convex hull).
  • Distance d(A,B) is the smallest gap, 0 if touching; penetrating depth is how deep shapes overlap, used to push them apart and stop sinking.
  • Discrete checks each frame and may miss fast objects; continuous predicts between frames and prevents tunneling.
